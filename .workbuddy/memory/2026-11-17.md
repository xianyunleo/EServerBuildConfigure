# 2026-11-17

## PHP 7.3 官方源码 macOS arm64 构建排查

目标：用官方 php.net 源码（非 backports）+ `--enable-opcache` 编译 PHP 7.3.33，CI 跑通。

### 已定位的失败链（按顺序）
1. configure 阶段 intl 编译失败：ICU 78 把 `BreakIterator::operator==` 返回类型从 `UBool` 改 `bool`，官方源码 `codepointiterator_internal.h` 不匹配 → 需 apply `0001-ICU-70.1` 补丁。
2. `0011-libxml2-2.13` 补丁 clean apply 失败 → 项目用 libxml2@2.11（2.11.9），该补丁不需要，已移除。
3. make 链接 `_zend_sort` 未定义 → opcache shared module 引用主程序符号。
4. 加 `-Wl,-export_dynamic` 后 `_zend_sort` 消失，变 `_OnUpdateBool` 未定义（同样 opcache 引用主程序 `Zend/zend_ini.c` 的 OnUpdateBool）。
5. 加 `-Wl,-undefined,dynamic_lookup` 到全局 LDFLAGS → configure 直接 exit 1（干扰 configure 的 conftest 链接检测），不可行。

### 根因
- `MACOSX_DEPLOYMENT_TARGET=11.0` 时，PHP 7.3 的 libtool darwin 分支 `_lt_dar_allow_undefined` 的 case 只有 `10.*`，`11.0` 不匹配 → module（bundle）链接不带 `-undefined dynamic_lookup`，opcache.so 链接时不允许引用主程序的未定义符号（zend_sort/OnUpdateBool）。

### 正确的修复方向（未完成，下次继续）
- 不能在 configure 前把 `-undefined dynamic_lookup` 塞进 LDFLAGS（会破坏 configure 的 conftest 检测）。
- 应在 configure 之后、make 之前，只对 shared module 的链接规则（Makefile 里的 `opcache.la` 等）追加 `-undefined dynamic_lookup`，或用 `sed` 修改生成的 libtool 脚本里的 `allow_undefined_flag`。

### 其他确认
- 官方 7.3.33 的 `Zend/zend_sort.c` 已有 `ZEND_API void zend_sort()`（315 行），不是记忆里"只有 zend_qsort"。项目记忆该条需修正。
- 用户明确要求：只用官方源码、保留 `--enable-opcache`、不套 OpenSSL 4.0 补丁。
- 当前 openssl@1.1（1.1.1w）和 openssl@3.5 都在 Library 里；php-7.3.sh 的 PKG_CONFIG_PATH 加了 openssl@1.1 在前，但 configure 无 `--with-openssl`，故无影响。

### 最终修复（第 11 次成功）
- 在 configure 之后、make 之前，对生成的 `libtool` 脚本追加 `-undefined dynamic_lookup`：
  ```bash
  sed -i '' 's/^allow_undefined_flag=""$/allow_undefined_flag=" -undefined dynamic_lookup"/' "$(pwd)/libtool"
  ```
- 仅改 libtool 的 `allow_undefined_flag` 变量，不碰全局 LDFLAGS（避免破坏 configure conftest）。
- run 44120101189 全绿：Build / Show PHP info / Show file info / Package / Upload release 全部 success。
