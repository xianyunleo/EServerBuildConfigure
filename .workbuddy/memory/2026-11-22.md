# 2026-11-22

## php-7.4 构建改为官方 CVE 分支源码

- `mac_arm64/php/php-7.4.sh` 源码从 `php-src-backports-7.4.33.tar.gz` 改为 GitHub 分支归档
  `https://github.com/php/php-src/archive/refs/heads/PHP-7.4-CVE-2026-109618-109619.tar.gz`
  （解压目录 `php-src-PHP-7.4-CVE-2026-109618-109619`）。
- 应用补丁：0002（OpenSSL 3.0）、0003（bug79589）、0006（ITIMER_REAL）、0009（strict-prototypes）、
  0010（GH-16168 inline asm），全部可干净应用（0006 有 13 行 offset）。
- libxml2 版本冲突的处理（最终方案）：`Library/lib/pkgconfig/libxml-2.0.pc` 指向 `Library/libxml2`（2.15.3），
  而 2.12+ 删掉了 `ATTRIBUTE_UNUSED`，PHP 7.4 的 `ext/libxml/libxml.c:479` 因此报 `expected ')'`。
  PHP 7.4 的 `config0.m4` 没有 `--with-libxml-dir` 选项（7.3 有），libxml2 只能走 `PKG_CHECK_MODULES`，
  所以把 `PKG_CONFIG_PATH` 改成 `libxml2@2.11/lib/pkgconfig:.../lib/pkgconfig`，让 2.11.9 优先命中。
  不再需要额外补丁（试过 `ZEND_ATTRIBUTE_UNUSED` 补丁方案，已按用户要求删除）。
- `Library/libxml2@2.11` = 2.11.9（`xmlversion.h` 仍定义 `ATTRIBUTE_UNUSED`）；`Library/libxml2` = 2.15.3（已无该宏）。
- 删除对 `ext/curl/interface.c` 的 sed：BSD sed 不支持 `\s`，该行从未生效。
- git 分支归档不含 `configure`，patch 之后必须保留 `./buildconf --force`（已在脚本内）。
- `build-php-7.4.yml` 增加 `push: tags: 'php-7.4.*'` 与 `workflow_dispatch.inputs.tag`。
- 结果：CI 全部步骤成功（run 44994759644），release `php-7.4.33` 上传 `php-7.4.tar.xz`。

## CI 诊断技巧

- 匿名 API 无法读取 Actions 日志；改为脚本 ERR trap 把「行号 + make 错误摘要」写入
  `$GITHUB_WORKSPACE/failure.txt`，workflow 在 `if: failure()` 步骤里用 GITHUB_TOKEN 上报到
  commit status（`diag-php7.4-N`，每条 130 字符），之后用匿名
  `/repos/{owner}/{repo}/commits/{sha}/statuses` 读取。
- 上报前必须用 `sed "s#$PWD/##g"` 去掉长路径，否则错误文案会被路径占满截断。

## php-8.0 构建改为官方 CVE 分支源码

- `mac_arm64/php/php-8.0.sh` 源码从 `php-src-backports-8.0.30.tar.gz` 改为 GitHub 分支归档
  `PHP-8.0-CVE-2026-109618-109619`（与 7.4 保持一致）。
- 5 个补丁在分支源码上均可干净应用：0002 OpenSSL3.0（offset 104）、0003 bug79589、
  0006 ITIMER_REAL（offset 13）、0009 strict-prototypes（offset 2）、0010 GH-16168。
  注意 0009 文件名是 `PHP-8.0`（带连字符），不是 `PHP8.0`，容易写错。
- backports 源码包 `php-src-backports-8.0.30.tar.gz` 里这 5 个补丁已内置，
  所以脚本的 `apply_patch` 用 `patch -p1 -R --dry-run` 判断：已应用则跳过、未应用才打（幂等），
  避免 "Reversed (or previously applied)" 直接失败。
- 直接编译（PKG_CONFIG_PATH 只含 `Library/lib/pkgconfig`）会失败：
  `ext/libxml/libxml.c:431:47: error: expected ')'`，原因是 libxml-2.0 解析到 2.15.3，
  该版本已删除 `ATTRIBUTE_UNUSED`（backports 包里同一函数已改为 `int compression)`）。
  修复方式与 7.4 相同：`PKG_CONFIG_PATH=/Applications/EServer/Library/libxml2@2.11/lib/pkgconfig:/Applications/EServer/Library/lib/pkgconfig`。
- `build-php-8.0.yml` 增加 `push: tags: 'php-8.0.*'`、`Report failure info`（context `diag-php8.0-N`）。
- 脚本增加 ERR trap 写 `failure.txt`、`make ... | tee make.log`。
- 结果：run 44997787054 全绿，release `php-8.0.30` 上传 `php-8.0.tar.xz`（11.7 MB）。

## php-8.1 构建改为官方 CVE 分支源码

- `mac_arm64/php/php-8.1.sh` 源码从 php.net 发布包 `php-8.1.31.tar.gz` 改为分支归档
  `PHP-8.1-CVE-2026-109618-109619`，分支实际版本是 **8.1.34**（PHP_VERSION/workflow env 同步更新）。
- 只应用一个补丁：`0006-Use-ITIMER_REAL-for-timeout-handling-PHP-8.1.patch`（offset 15，幂等 apply_patch）。
- 分支不含 `configure`，patch 后 `./buildconf --force`；workflow 因此补了
  `Install dependencies`（autoconf/automake/libtool/bison/re2c）与 `Set Homebrew PATH`。
- 第一次失败：`ext/bcmath/libbcmath/src/add.c:46` 报
  `unknown type name 'n1' / expected identifier or '('` —— libbcmath 是 K&R 风格定义，
  新 clang 的 C23 默认不兼容。补 `CFLAGS += -std=gnu17`（与 7.x/8.0 一致）后通过。
- **8.1 不需要 libxml2@2.11 覆盖**：分支里 `int compression)` 已无 `ATTRIBUTE_UNUSED`，
  且 `php_libxml_structured_error_handler` 用 `#if LIBXML_VERSION` 区分 const，
  直接用 2.15.3 即可，PKG_CONFIG_PATH 保持 `Library/lib/pkgconfig`。
- workflow 增加 `Report failure info`（context `diag-php8.1-N`）。
- 结果：run 44999031067 全绿，release `php-8.1.34` 上传 `php-8.1.tar.xz`（13,443,600 字节）。
  旧 tag `php-8.1.31` 及其 release 保留未动。
