# 2026-11-22

## php-7.4 构建改为官方 CVE 分支源码

- `mac_arm64/php/php-7.4.sh` 源码从 `php-src-backports-7.4.33.tar.gz` 改为 GitHub 分支归档
  `https://github.com/php/php-src/archive/refs/heads/PHP-7.4-CVE-2026-109618-109619.tar.gz`
  （解压目录 `php-src-PHP-7.4-CVE-2026-109618-109619`）。
- 应用补丁：0002（OpenSSL 3.0）、0003（bug79589）、0006（ITIMER_REAL）、0009（strict-prototypes）、
  0010（GH-16168 inline asm），全部可干净应用（0006 有 13 行 offset）。
- libxml2 版本冲突的处理（最终方案）：`Library/lib/pkgconfig/libxml-2.0.pc` 指向 `Library/libxml2`（2.15.3），
  而 2.12+ 删掉了 `ATTRIBUTE_UNUSED`，PHP 7.4 的 `ext/libxml/libxml.c:479` 因此报 `expected ')'`。
  PHP 7.4 的 `config0.m4` 没有 `--with-libxml-dir` 选项（7.3 有），libxml2 只能走 `PKG_CHECK_MODULES`，
  所以把 `PKG_CONFIG_PATH` 改成 `libxml2@2.11/lib/pkgconfig:.../lib/pkgconfig`，让 2.11.9 优先命中。
  不再需要额外补丁（试过 `ZEND_ATTRIBUTE_UNUSED` 补丁方案，已按用户要求删除）。
- `Library/libxml2@2.11` = 2.11.9（`xmlversion.h` 仍定义 `ATTRIBUTE_UNUSED`）；`Library/libxml2` = 2.15.3（已无该宏）。
- 删除对 `ext/curl/interface.c` 的 sed：BSD sed 不支持 `\s`，该行从未生效。
- git 分支归档不含 `configure`，patch 之后必须保留 `./buildconf --force`（已在脚本内）。
- `build-php-7.4.yml` 增加 `push: tags: 'php-7.4.*'` 与 `workflow_dispatch.inputs.tag`。
- 结果：CI 全部步骤成功（run 44994759644），release `php-7.4.33` 上传 `php-7.4.tar.xz`。

## CI 诊断技巧

- 匿名 API 无法读取 Actions 日志；改为脚本 ERR trap 把「行号 + make 错误摘要」写入
  `$GITHUB_WORKSPACE/failure.txt`，workflow 在 `if: failure()` 步骤里用 GITHUB_TOKEN 上报到
  commit status（`diag-php7.4-N`，每条 130 字符），之后用匿名
  `/repos/{owner}/{repo}/commits/{sha}/statuses` 读取。
- 上报前必须用 `sed "s#$PWD/##g"` 去掉长路径，否则错误文案会被路径占满截断。
