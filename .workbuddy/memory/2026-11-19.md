## 结论：php-7.3 不能把 libxml 从 @2.11 换到 libxml2 (2.15.3)

- 版本事实：`Library/libxml2` = **2.15.3**（SONAME `libxml2.16.dylib`），`Library/libxml2@2.11` = **2.11.9**。两者差 4 个大版本，不是路径别名。
- 实测（临时 workflow `test-php-7.3-libxml2.yml`，tag `php-7.3-libxmltest-1`，run 44322094799，两个变体并行）：
  - 变体 A：换路径 + 保留 0007 → 失败
  - 变体 B：换路径 + 去掉 0007 → 失败
  - 两处报错相同：`build/php-7.3.33/ext/libxml/libxml.c:434:47: error: expected ')'`，位置在
    `php_libxml_output_buffer_create_filename(const char *URI, ... int compression ATTRIBUTE_UNUSED)` 的第三参数上，
    note 指向 432:41 的函数左括号。
- 根因：libxml2 2.13 起大改输出回调/结构化错误回调的类型（`xmlOutputBufferCreateFilenameFunc`、`xmlStructuredErrorFunc` 等）。
  PHP 官方直到 **8.4** 才加入 libxml2 2.13+ 支持，7.3 没有对应适配；仅靠 0007（GH-14834，只动 `ext/xml/compat.c`）不够。
- 决策：php-7.3 继续使用 `--with-libxml-dir=/Applications/EServer/Library/libxml2@2.11`。
  若将来一定要上 2.15，需要自写一套 2.13+ 移植补丁（ext/libxml、ext/dom、ext/soap 全套），成本很高。
- 清理：临时 workflow 与 tag 均已删除（commit b77d67c → 3129cf8）。

## 后续验证：加 0011 后 libxml2 2.15.3 可以编译通过（run 44529287917，Success 5m19s）

- 补丁来源：`patch/php/0011-Backport-4fe82131-Backport-libxml2-2.13.2-fixes-1481-PHP7.3.patch`
  （shivammathur/php-src-backports，对应 GH-14817）。
- 关键命中：0011 对 `ext/libxml/libxml.c` 的 hunk 正是上面那次报错的解药——
  把 `int compression ATTRIBUTE_UNUSED` 改成 `int compression` + `ZEND_IGNORE_VALUE(compression);`（libxml2 2.13+ 里该参数不再 UNUSED）。
- 但 0011 整份**打不干净**（相对官方 php.net 7.3.33 tarball，不是 backports 树）：
  - `ext/dom/document.c`：2 个 hunk 中 1 个失败（`ctxt->recovery = recover` → `options |= XML_PARSE_RECOVER`，
    以及 `ctxt->recovery` → `recover`）。失败后仍能编译，但 `DOMDocument::loadXML(..., LIBXML_RECOVER)` 的恢复行为可能变味。
  - `ext/soap/php_xml.c`：2 个 hunk 全失败，内容只是去掉 `#if LIBXML_VERSION >= 20703` 保护 + 加 TODO 注释，纯形式，无影响。
- 结论修正：libxml2 2.15.3 **技术上可用**（编译 + 运行时 smoke test 均通过：dom/simplexml/soap/xml 模块加载、
  DOMDocument 解析与 saveXML 正常）。若要正式切换，推荐自写**精简补丁**只保留 `ext/libxml/libxml.c` 那一个 hunk
  （可选再按官方源码重做 dom/document.c 的 recover 适配），并跑 ext/libxml、ext/dom、ext/soap 的 phpt。
- 清理：临时 workflow `test-php-7.3-libxml2-0011.yml` 与 tag `php-7.3-libxml0011-1/2` 已删除（commit 4160206 → 50dc6b6）。

## 0011 整份应用的精确定位（本地按官方 7.3.33 源码 patch --dry-run 复现）

- `ext/dom/document.c`：**hunk #1 FAILED（1435）**、hunk #2 成功。原因：0011 的上下文含
  `php_libxml_sanitize_parse_ctxt_options(ctxt);`，这是 PHP 8.x 才引入的函数，官方 7.3.33 没有该行。
- `ext/soap/php_xml.c`：2/2 hunk 失败，内容仅为去掉 `#if LIBXML_VERSION >= 20703` 与加 TODO 注释，纯形式无影响。
- `ext/xml/compat.c`：成功（offset -2），与 0007 不冲突。
- 副作用风险：hunk#1 失败导致 `ctx->recovery = recover;` 保留、`options |= XML_PARSE_RECOVER;` 缺失；
  而 libxml2 2.13+ 已把 `xmlParserCtxt.recovery` 标记 deprecated 并改用 `XML_PARSE_RECOVER` 选项，
  于是 `DOMDocument::loadXML(..., LIBXML_RECOVER)` 在 2.15 下**静默失效**。
- 另：脚本 `set -euo pipefail`，patch 有 reject 返回 1 会中断构建，整份 0011 必须 `|| true` 才能用。

## 最终决策（2026-11-19 定稿）

**php-7.3 维持 `--with-libxml-dir=/Applications/EServer/Library/libxml2@2.11`，不切 2.15.3。**
理由：切 2.15 需要自写 0012（libxml.c 的 compression 签名 + dom/document.c 的 XML_PARSE_RECOVER 适配），
虽然已验证可 100% 干净应用，但收益不抵风险（7.3 已 EOL，官方直到 8.4 才支持 libxml2 2.13+）。
`php-7.3.33` 正式产物保持 2.11 版本，脚本与 patch 列表未做任何改动。
若将来必须升级，直接取本次验证过的 0012 方案（见上），不要用整份 0011。

## php-7.2 ext/intl TRUE/FALSE 报错根因（commit 4c217e2，run #4 Success 8m28s）

**根因：** ICU 68 起公共头文件默认不再定义 `TRUE`/`FALSE`
（`Library/icu/include/unicode/umachine.h:283-307`，`U_DEFINE_FALSE_AND_TRUE` 默认 0）。
PHP 7.2 的 `ext/intl` 仍在用这两个宏（collator_sort.c:349/543、dateformat_attr.c、normalizer_normalize.c、
timezone_class.cpp、codepointiterator_internal.cpp、timezone_methods.cpp），因此 `undeclared identifier 'TRUE'/'FALSE'`。

**为什么 7.3 不报错（关键）：** 同一份 intl 代码 7.3 也用了 TRUE/FALSE，但 7.3 的 `acinclude.m4:2258`
在 `PHP_SETUP_ICU` 里无条件追加 `ICU_CFLAGS="$ICU_CFLAGS -DU_DEFINE_FALSE_AND_TRUE=1"`，
且 7.3 的 `ext/intl/config.m4:12` 把 `$ICU_CFLAGS` 拼进了 `INTL_COMMON_FLAGS`。
7.2 两处都没有 → 宏不生效。

**最终方案（不用自写源码补丁）：** `php-7.2.sh` 里
`export CFLAGS=... -DU_DEFINE_FALSE_AND_TRUE=1` 和 `CXXFLAGS=... -DU_DEFINE_FALSE_AND_TRUE=1`
（intl 以 cxx 编译，必须同时给 CXXFLAGS）。效果等同 7.3 的做法，零源码改动。
自写的 `0013-Fix-TRUE-FALSE-macros-PHP7.2.patch` 已删除（仅作为中间产物存在过，未进最终仓库）。
